## Tasks
- task-1: Write `package.json`, `pnpm-workspace.yaml`, and `.gitignore`. `package.json` holds the pinned dependencies and these scripts: `typecheck` runs `tsc` for the node and web projects, `test` runs the Vitest `unit` project, `test:integration` runs the Vitest `integration` project, `build` runs `electron-vite build`, `dev` runs `electron-vite dev`. Also write the tsconfig files, `electron.vite.config.ts`, and `vitest.config.ts`. Run `pnpm install`, resolve every `ERR_PNPM_IGNORED_BUILDS` entry through `allowBuilds`, then confirm `pnpm install --frozen-lockfile` is clean. Verify `electron` actually downloads its binary.
- task-2: Write the failing test `test/unit/window.test.ts` first. It asserts, from the pure function `buildWindowOptions()` and the `CSP` constant exported by `src/main/window.ts`, that `sandbox` is `true`, `contextIsolation` is `true`, `nodeIntegration` is `false`, and that the CSP contains `default-src 'self'`, contains no `unsafe-eval`, and contains no `unsafe-inline` for production. To get a behavioral RED, first add inert scaffolding that exports the two names with wrong values, run the test, confirm the assertion failure, then implement. Implement `window.ts` (also `will-navigate` blocking, and `setWindowOpenHandler` that calls `shell.openExternal` only for `https:` URLs and always returns `{ action: 'deny' }`, and a CSP response header or meta set for every window), `index.ts`, and `src/preload/index.ts` (exposes an empty frozen `api` through `contextBridge`). Implement the renderer placeholder (`index.html`, `main.tsx`, `App.tsx`). Prove the test fails if any of the three settings is flipped or if the CSP lacks `default-src 'self'`, and record that in `notes.md`.
- task-3: Write `test/rustfs/compose.yaml` with image `rustfs/rustfs:1.0.4` (never `latest`), host port `19000` mapped to container port `9000`, default credentials `rustfsadmin`/`rustfsadmin`, and a tmpfs or named-volume data dir. Read the RustFS image documentation or `docker run --rm rustfs/rustfs:1.0.4 --help` to get the exact command, environment variables, and data path before writing; do not guess flags. Write `test/integration/global-setup.ts`, which runs `docker compose -f test/rustfs/compose.yaml up -d`, polls until a `ListBuckets` call with `rustfsadmin`/`rustfsadmin`, `forcePathStyle: true`, endpoint `http://127.0.0.1:19000`, and region `us-east-1` succeeds within 60 s, and in teardown runs `docker compose -f test/rustfs/compose.yaml down -v`. Write `test/integration/rustfs.test.ts`, which creates a bucket, puts an object, and reads it back with a `Range` header that yields a 206 response and the expected bytes. The integration test is RED first (no harness), then GREEN.
